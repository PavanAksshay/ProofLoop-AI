# Dataset Licenses, Provenance, and Governance

## 1. Overview and Purpose

This document provides verified provenance, licensing, and compliance documentation for real-world operational datasets used to evaluate the autonomous diagnosis capabilities of **ProofLoop AI**.

ProofLoop AI evaluates whether an incident investigation agent can correctly hypothesize and diagnose operational failures in distributed microservice architectures using telemetry, logs, Kubernetes object snapshots, and configuration states—**without** accessing evaluator ground truth in advance and **without** mutating live infrastructure.

## 3. License Verification and Terms

### Upstream License: MIT License
The upstream repository and dataset distribution are published under the standard MIT License:
- **Permission**: Free to use, copy, modify, merge, publish, distribute, sublicense, and/or sell copies of the Software and dataset artifacts.
- **Condition**: The copyright notice and permission notice must be included in all copies or substantial portions of the Software.
- **Third-Party Subcomponents**: Embedded application source files (such as Google Microservices Demo) retain their original licenses (e.g., Apache 2.0). Cloud-OpsBench does not claim original authorship of these third-party demonstration microservices.

### Privacy and Secret Audit
- **No PII**: All telemetry, user IDs, and transaction records are generated by synthetic load generators (Locust / JMeter) simulating traffic against open-source demo applications.
- **No Production Credentials**: Kubernetes manifests in snapshots utilize dummy secrets and cluster-internal service accounts; no commercial cloud provider keys, production API tokens, or private infrastructure credentials exist within the distributed artifacts.

## 4. Repository Redistribution Policy

To maintain repository hygiene and avoid bloat:
1. **Never commit large raw data files**: The full 3.8GB dataset snapshots reside in `.gitignore` under `datasets/raw/` and `datasets/downloaded/`.
2. **Version-controlled manifests**: The official manifest (`datasets/manifests/cloud_opsbench.json`) documents cryptographic file sizes, tree hashes, source URLs, and category distributions.
3. **CI/Regression Fixtures**: A minimal, sanitized fixture (`datasets/fixtures/cloud_opsbench_sample.json`) containing representative Online Boutique and Train-Ticket cases is maintained in Git for 100% offline testing.
4. **Retrieval Tooling**: An automated, verified downloader script is provided for operators who wish to evaluate against the full 754-case distribution.

## 5. Dataset Schema & Architecture

Cloud-OpsBench organizes each incident snapshot as follows:
```text
benchmark/<system>/<category>/<case_id>/
    metadata.json       # Case description, difficulty, ground-truth label
    tool_cache.json     # Pre-recorded read-only tool responses (kubectl, metrics, logs)
    raw_data/           # Raw control plane dumps
    code/               # Microservice source code (Online Boutique)
golden-trajectory/<system>/<category>/<case_id>/
    path1.json          # Expert diagnostic path A (Evaluator only)
    path2.json          # Expert diagnostic path B (Evaluator only)
process-label/<system>/<category>/<case_id>/
    milestone.json      # Process milestone dependency graph (Evaluator only)
index.jsonl             # Master catalog mapping case_key to paths and metadata
manifest.json           # SHA256 checksums of all distributed files
release.json            # Distribution metadata, tree IDs, and category counts
```

## 6. Ground-Truth Leakage Governance

The Cloud-OpsBench official distribution explicitly mandates:
> *"Task agents should receive the incident query/namespace and acquire observations through diagnostic tools. Ground-truth `result` fields, milestone labels, and golden trajectories are evaluator/research resources; do not expose them to an agent during benchmark evaluation."*

ProofLoop AI strictly enforces this boundary at the data layer:
- The adapter strips all evaluator-only fields (`root_cause`, `fault_object`, `fault_taxonomy`, `trajectory_paths`, `milestone_path`) into an isolated `EvaluatorGroundTruth` object.
- The investigation engine receives only the `AgentIncidentInput` payload.
- Automated regression tests verify that serialized agent payloads contain zero ground-truth keys.
